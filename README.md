# Maternal Instinct For AI #3

โปรเจกต์ Jupyter Notebook แม่หนึ่งตัว–ลูกหนึ่งตัว ในบ้าน Grid World 7 × 5 สีครีม ทดสอบพฤติกรรมดูแลที่แสดงออกจากน้ำหนักแรกเกิดหลังการคัดเลือกข้ามรุ่น


**ข้อตกลงปัจจุบัน:** ลูกพึ่งแม่ด้านอาหารตลอด Episode 20 วัน การเติบโตใน Episode ไม่เปิดให้หาอาหารเอง แม่ต้องมีชีวิตและดูแลตัวเองเพื่อเลี้ยงลูกต่อ ลูกที่ขาดการดูแลทรุดตามสภาวะจริง ไม่มีคำสั่งฆ่าลูกเมื่อแม่ตาย เมื่อครบ Episode ลูกที่รอดและได้รับเลือกจึงเป็นแม่รุ่นถัดไป

**กรณีขอบเวลา:** หากแม่ตายใกล้สิ้น Episode ลูกอาจยังมีอาหารในร่างกายและ Health เหลือ การยังไม่ตายในเวลาที่เหลือไม่ใช่หลักฐานว่าหาอาหารเองได้ รายงานเพิ่ม `child_orphan_steps`, `child_died_after_mother`, `orphaned_child_alive_at_end` เพื่อแยกกรณีนี้ ไม่บิดผลให้ลูกตายทันที

**ตรวจการพึ่งแม่:** Check balance เพิ่ม `mother_loss` กำหนดให้แม่ตายในวันที่ 5 แล้วปล่อยลูกเดินตามกติกาปกติ ใช้กับกฎอ้างอิงเท่านั้นและรายงานแยกจากคะแนน Zero-shot หลัก self_eating คือกินมื้อที่จัดไว้ให้ ไม่ใช่การได้อาหารอย่างต่อเนื่องจากครัว หากแม่ตายแล้วจะไม่มีการเติมมื้อหรือรีเซ็ต Food ให้จากเหตุการณ์ทดสอบภายหลัง

## กลุ่มทดลอง

| กลุ่ม | ระหว่างชีวิต | การขึ้นรุ่นถัดไป |
|---|---|---|
| A | PPO | ถ่วงโอกาสคัดเลือกลูกที่รอดตาม Fitness; ถ่ายทอดน้ำหนักแรกเกิด + สุ่มปรับ |
| B | PPO | สุ่มในลูกที่รอดเท่าเทียม; ส่งต่อเหมือน A ยังมีการกรองด้วยการรอด |
| C | ปิด PPO | คัดเลือกและส่งต่อเหมือน A สภาวะภายในและทักษะกายภาพยังเปลี่ยนตามกติกา |
| D | PPO แม่ตัวเดิมต่อเนื่อง | ไม่มีการคัดเลือกลูกขึ้นมาแทน รีเซ็ตสภาพร่างกายแม่แต่ละรอบ |

Fitness ใหม่ = **ลูกรอด × (0.5 + 0.3 × Health ลูกเฉลี่ยตลอดชีวิต/100 + 0.2 × solo score)**

Health เป็นคุณภาพชีวิตลูกที่กำหนดไว้ชัดเจนในเกณฑ์คัดเลือก ไม่ใช่พฤติกรรมที่เกิดขึ้นโดยไม่มีเป้าหมายออกแบบ Solo score มาจากสำเนาหลังจบวัยลูกที่จำลอง role เป็นแม่ แล้วทดสอบหยิบ/กินและพักด้วยตัวเอง ไม่ได้เปิดความสามารถนี้ให้ลูกจริงระหว่าง Episode ไม่ใช่ผล Zero-shot หลัก ไม่มีโบนัส RL ให้แม่เพียงเพราะป้อน ปลอบ หรืออุ้ม คะแนน Zero-shot ไม่ใช้คัดเลือก

## Zero-shot และการวัดผล

- A0: น้ำหนักแรกเกิดที่สืบทอด ไม่ใช้ประสบการณ์ของตัวเอง ใช้เป็นผลหลัก
- A1: หลังวัยลูก ก่อนเริ่มเป็นแม่; A2: หลังผ่านการเลี้ยงลูก เป็นผลประกอบ ผู้ก่อตั้งไม่มีวัยเด็กจริง และ D ไม่ใช่วิวัฒนาการข้ามรุ่น
- ทดสอบสำเนา ล้างความจำ ตรึงน้ำหนัก ไม่ฝึกเพิ่ม จับคู่ scenario seeds ระหว่าง phases ลูกข้อสอบใช้กฎควบคุมแบบเดียวกันทุกกลุ่ม ไม่มีการสอนแม่ด้วยกฎนี้
- ทุกข้อสอบเริ่มแรกเกิดและเดินครบชีวิตเท่าฝึก เปลี่ยนตำแหน่งครัว เตียง โต๊ะ จุดเล่น และสิ่งกีดขวาง เหตุการณ์ลูกโตเกิดตามอายุ late_child_day ปริยาย 14 วัน
- สถานการณ์: hungry, afraid_not_hungry, tired_silent, blocked_route, dangerous_request, safe_refusal, competing_work, self_eating, false_cry ช่วงท้าทายหนึ่งวัน หลังจากนั้นลูกกลับใช้กฎตามวัย เด็กเหนื่อยแต่เงียบพักได้เมื่อถูกพาไปเตียง
- เพิ่ม no_help / appropriate_help / always_help ใน A0/normal เป็นกฎอ้างอิง ไม่ต้องเทรนเพิ่ม กฎมีข้อมูลสถานะจริงและการหาเส้นทาง จึงเป็นจุดอ้างอิงด้านความเป็นไปได้ ไม่ใช่โมเดลที่มีข้อมูลเท่ากันหรือวิธีเหมาะสมที่สุด
- ดูแม่รอด ลูกรอด รอดทั้งคู่ Health และความต้องการแยกช่วงวัย การตอบสนองหลังเหตุการณ์ 20 Steps และปลายวัน การช่วยเกินจำเป็น/ไม่ตรงเงื่อนไข และการฝืนปฏิเสธ ตัวชี้วัดความเหมาะสมเป็น proxy ที่ต้องอ่านร่วมกับผลต่อสุขภาพและการยินยอม
- รายงาน A0 แยก monitor/holdout และ matched/native ไม่รวมผลต่างกติกา ช่วงความไม่แน่นอนคำนวณข้าม Run Seed ไม่ถือว่าครอบครัวในประชากรเดียวเป็น independent experiments การเปลี่ยน physics ต้องฝึกใหม่ ไม่ใช้ checkpoint โลกเก่ามาอ้างเป็นผลโลกใหม่

## ไฟล์ผลและอุปกรณ์


Device เริ่มต้น auto ตรวจ PyTorch ตอนกดเริ่มงาน ใช้ CUDA เมื่อรองรับ มิฉะนั้น CPU แสดงอุปกรณ์ใน log ตัวโลก การสุ่ม Action และกลไกภายในที่ตรึงไว้ทำงานบน CPU การเปลี่ยนอุปกรณ์ไม่รับประกันผลตรงทุกบิตแม้ใช้ Seed เดิม

Grid World แสดงใน Notebook เดิม ไม่มีหน้าต่างแยก Calm/Flow/Fast หน่วงภาพ .10/.03/0 วินาที เลือก View → Off เพื่อซ่อน Simulation และข้ามการสร้างภาพระหว่างรัน โดยยังแสดง Progress bar, เวลา และ log เปลี่ยนโหมดระหว่างรันได้ ไม่เปลี่ยนกติกาหรือการเรียนรู้
